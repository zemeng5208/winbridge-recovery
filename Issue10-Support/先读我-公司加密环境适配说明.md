# Issue #10：公司加密 / EDR 环境适配包说明

这个分支是给 Issue #10 的临时支持包。它包含 WinBridge 当前仓库的完整脚本源码，以及本目录下针对公司加密、DLP、EDR、终端防护环境的补充诊断资料。

## 最重要：不要直接运行原版脚本

**第一步不是运行 WinBridge。**

请先把这个解压后的整个文件夹、Issue #10 的报错日志、以及你们公司加密/安全软件的名称或截图，一起交给你自己电脑上使用的 GPT。

让 GPT 先检查并按你这台机器的真实环境适配脚本，再由你确认修改内容后运行。

推荐把 `Issue10-Support/GPT-适配提示词.txt` 原样交给 GPT，并把整个源码目录一起提供给它。

## 推荐顺序

1. 下载并解压整个 ZIP 到普通本地目录，例如：
   `C:\WinBridge-Issue10\`
2. **暂时不要双击 `START-BEFORE-DESKTOP.cmd`。**
3. 把整个解压目录 + 原始报错日志 + 公司加密/EDR/DLP 软件信息交给你自己的 GPT。
4. 让 GPT 先审查这些脚本，重点判断：
   - 公司加密/终端防护是否会拦截 `.codex\plugins\cache\openai-bundled\chrome` 的 rename / move / delete；
   - 是否存在文件系统 minifilter、DLP、透明加密、EDR、自保护或应用控制；
   - WinBridge 的原子目录切换逻辑是否需要针对该环境调整重试、等待、诊断或跳过策略；
   - **不要尝试绕过公司安全策略。**
5. GPT 给出改动后，先看一遍 diff。以下安全边界不要删：
   - 不修改 `C:\Program Files\WindowsApps` 的所有权或 ACL；
   - 不 `takeown` 整个 `.codex`；
   - 不 `icacls /reset` 整个 `.codex`；
   - 不关闭、卸载或绕过公司加密 / EDR / DLP；
   - 不结束所有 `node.exe`；
   - 保留 Recovery Backup、回滚和完整性校验。
6. 修改完成后，先完全退出 ChatGPT / Codex Desktop、Chrome、Edge。
7. **先运行只读诊断：**
   `Issue10-Support\Diagnose-WinBridge-Lock.ps1`
8. 把生成的 `Issue10-Diagnosis-*.txt` 再交给 GPT 看一次。
9. 只有在诊断结果没有显示公司策略明确阻止，而且 GPT 的修改没有削弱上述安全边界时，再运行：
   `DIAGNOSE-ONLY.cmd`
10. Diagnose-only 正常后，再考虑运行：
   `START-BEFORE-DESKTOP.cmd`

## 当前 Issue #10 的已知失败点

目标目录：

`%USERPROFILE%\.codex\plugins\cache\openai-bundled\chrome`

失败阶段：`Install-DirectoryAtomically`

失败操作本质上是把现有 Chrome 插件缓存目录重命名/移动到旧目录，Windows 返回 `Access Denied`。

这类结果既可能来自普通进程文件锁，也可能来自公司透明加密、DLP、EDR、文件系统过滤驱动、ACL/Delete 权限或目录句柄。

## 依赖

### 必需

- Windows 10 / Windows 11
- Windows PowerShell 5.1 或更高版本
- 已正常安装的官方 Codex Desktop / 对应 Microsoft Store 包
- 当前 Windows 用户对自己的 `%USERPROFILE%\.codex` 目录具有正常用户权限

### 不需要额外安装

核心脚本不依赖第三方 PowerShell 模块。WinBridge 所需的官方 Codex/插件/runtime 内容由脚本从**用户本机已安装的官方包**中识别和读取，本支持包不会重新分发官方受保护二进制或插件 payload。

### 可选

Microsoft Sysinternals `handle.exe` / `handle64.exe`。如果已经安装并在 PATH 中，诊断脚本会自动调用；没有也可以运行，其余检查仍会执行。

## 如果公司软件就是根因

如果日志最终显示公司安全产品、透明加密驱动、DLP/EDR 或组织策略在阻止该目录 rename/move，请优先让公司 IT/安全策略管理员确认是否允许对该目录做这类操作。

WinBridge 不应该通过停用、卸载、注入、驱动绕过、ACL 强夺等方式规避公司安全控制。

## 需要回传的东西

如果适配后仍失败，请回到 Issue #10，最好提供：

- `Issue10-Diagnosis-*.txt`
- 最新的 `Logs\run-*.log`
- GPT 修改了哪些文件（diff 或简述）
- 公司加密/EDR/DLP 软件名称（能公开的话）
- 是否仍然是同一个 `openai-bundled\chrome` Access Denied

这样我们就能区分：普通 Codex 文件锁、公司安全软件、ACL/Delete 权限、文件系统过滤驱动，还是 WinBridge 自身的原子切换逻辑问题。
